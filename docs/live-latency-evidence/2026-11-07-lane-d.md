## TTS first audio: HTTP against the websocket miss transport (2026-11-07)

`node --experimental-strip-types scripts/measureTtsFirstAudio.mjs <tutor .env> <report> --transports http,ws --reps 2`,
`eleven_multilingual_v2`, voice alexandre, 12 non-authored French tutor sentences per rep through
`buildTTS` off the paid proxy on a developer machine (3,256 characters billed). Report
`2026-11-07-tts-first-audio.json`. This is vendor first audio through the cache wrapper, not phone
audible latency.

| transport | n | cold first frame (rep 1, rep 2) | warm first frame p50 | warm p95 | last frame p50 |
|---|---|---|---|---|---|
| http (per-sentence `/stream`) | 24 | 1,313, 275 ms | **329 ms** | 380 ms | 370 ms |
| ws (`multi-stream-input`) | 24 | 546, 506 ms | 437 ms | 554 ms | 438 ms |

The websocket is slower at p50 by about 110 ms, and it hands each sentence back in one piece
(first and last frame within 1 ms), so playout cannot start on a partial sentence. The TLS cost
the ws path was meant to save shows only on the very first sentence of a cold process (1,313 ms
once; Node reuses the connection after that). Decision: `LUVANI_TTS_MISS_TRANSPORT=ws` stays a
dev-only knob; the paid proxy does not get an ElevenLabs websocket route. Stitching
(`LUVANI_TTS_STITCH`) therefore ships on the HTTP path only.
